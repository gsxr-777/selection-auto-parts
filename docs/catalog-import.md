# Импорт и подбор автомобилей / запчастей

09.10.2026 владелец проекта подтвердил наличие разрешения на извлечение данных
установленного TecDoc и публикацию в приложении. Это подтверждение пользователя,
а не независимая юридическая проверка договора. Прежний блокер отсутствия
подтверждения снят. Исходные файлы, DLL, экспорт и секреты не публикуются в Git.
Название поставщика исключается из интерфейса; источник, версия и разрешение
сохраняются во внутренней таблице `catalog_sources` и документации.

Источник: BDF-каталог 2/2018, штатный reader 1.3.3.0; контекст страны RUS,
исходные переводы en/ru. Это исторический снимок, не текущий каталог.
Нет импорта цен, остатков, изображений или VIN.

Проверенный итоговый результат 09.10.2026: локальная и облачная БД содержат
596 марок, 11 631 модель автомобилей / 68 339 модификаций и 1 543 модель мотоциклов /
7 504 модификации. Для Focus: 1 152 исходные категории, 11 305 деталей от 477
производителей, 26 571 связь применимости/групп, 733 224 исходные OE-ссылки и 682
типизированных отношения замены. Облачная БД занимает около 454 МБ, локальная — 455 МБ
до повторного импорта. В фильтре доступны 559 групп с деталями и их предков;
остальные узлы исходного дерева сохраняются в БД. Оба языковых прохода и дополнительное
чтение родительских узлов завершены. Образцы проверены перед полным импортом;
повторный импорт использует те же ключи и не добавляет дубликатов.

Фотографии запчастей не импортировать (уточнение владельца 09.10.2026).
Будущий клиентский поиск изображений: запрос производитель + артикул,
показ внешних результатов со ссылкой на источник и возможностью выбора.
Не считать найденное изображение подтверждённым изображением каталожной позиции.
Способ интеграции Google Images/API, условия и требования к ключам уточняются
в отдельной фазе; в текущем интерфейсе незавершённая кнопка не добавляется.

Этапы: экспорт → проверка полей и внешних ключей → пробный импорт Focus →
повторный импорт для проверки идемпотентности → полный справочник автомобилей
и мотоциклов. Исходные группы/позиции запчастей были импортированы только для
`car:18953`: FORD FOCUS II Saloon (DB_), 1.6, 74 kW, 04.2005–09.2012.
Дополнительные подтверждённые связи расширяются отдельным проходом ниже.
Для модификаций без импортированных связей отсутствие запчастей показывается явно.

Идентификаторы моделей и типов включают вид (`car:` / `motorcycle:`),
марки используют исходный ID. Метки хранятся JSON по локалям без дублирования
сущностей. Пустая метка CHERY 11438 сохраняется как partial. Сохраняются
исходные атрибуты и ограничения применяемости, нормализуются только известные
значения топлива/кузова/коробки. Неизвестная коробка не считается МКПП/АКПП.

Запчасти идентифицируются парой поставщик + исходный артикул. Применяемость
проверяется штатным reader для точного типа. OE-ссылки и отношения замен
хранятся отдельно: наличие общего OE-номера или одной категории не доказывает
взаимозаменяемость. Результат показывает применяемые aftermarket-позиции,
их OE-номера и явно типизированные подтверждённые замены.

Классификация OE проверена по исходному `IManufacturer.IsVGL`: все 733 224
импортированные ссылки относятся к производителям с `IsVGL=false`. Название
производителя не используется для догадок о типе номера. Вспомогательный режим
`tools/catalog/run-export.ps1 -Mode reference-manufacturers` сохраняет RU/EN-справочник
в `.cache/catalog-reference-export`; импорт проверяет завершение, согласованность
флагов, наличие всех производителей и отклоняет сравнительные номера вместо их
публикации как OE. Хеш этого справочника, дата чтения и число проверенных ссылок
записываются в `import_batches.counts.referenceAudit`. Описание признака сравнения
есть в таблице 100 официального формата, а ссылки на производителей — в таблице 203.

Полный импорт: `node scripts/import-catalog.cjs --validate`, затем
`node scripts/import-catalog.cjs` и `node scripts/import-catalog.cjs --production`.
Проверка обеих БД: `node scripts/verify-catalog.cjs --full`. Миграции должны быть применены
до импорта; production-URL берётся только из игнорируемого `.env.production.local`.

Направление замен проверено по таблице 204 в
[официальном описании формата](https://dwnld.aws.tecalliance.com/TecDoc/Downloads/TecDoc-Data-Format.pdf):
текущий артикул заменяет указанный прежний артикул. Исходные `ReplaceNumbers`
сохраняются как `replaces`, обратные `NewNumbers` — как `replaced_by`.
Поставщик/артикул остаются исходными; это не автоматически построенные аналоги.

У трёх родительских узлов есть отдельные товары вне дочерних узлов. Дополнительный
проход `--parent-parts` включает их; строки находятся в `.cache/catalog-parent-export`.
После завершения обеих локалей этого прохода первичный образец проверяется командой
`node scripts/import-catalog.cjs --sample --parent-sample`. Повтор команды должен
сохранить количества строк и связи. Это небольшой образец кузовных/световых групп;
основной полный импорт без `--parent-sample` объединяет оба прохода и все группы Focus.
Импорт требует метки полного завершения каждой локали и совпадения сохранённой
длины файла. Незавершённый проход не допускается в полный импорт.
Повторные связи одного артикула внутри порции могут иметь `_references=false`:
OE/замены уже записаны в предыдущей строке этого артикула и не сериализуются повторно.
Импортёр сохраняет последний полный набор ссылок каждой локали и требует его наличия.
Все связи применимости и условия записываются полностью. Старые строки без маркера
считаются полными; публичный API и схема базы от этого изменения не зависят.
Чтение выполняется небольшими порциями поставщиков с контрольными точками:
32-битный reader не должен удерживать весь распакованный каталог в памяти.
Успешные порции сохраняют контрольную точку с длиной файла; при совпадении длины
следующий процесс восстанавливает состояние без повторного разбора всего экспорта.
После аварийного завершения файл очищается только по завершённым узлам/запросам;
незаконченный хвост не считается импортированными данными. Для ускоренной проверки
на хосте используется `node scripts/repair-catalog-export.cjs [catalog-parent-export]`
при остановленном собственном помощнике. Каталог ВМ не затрагивается.
Завершённые запросы сохраняются; незавершённая порция удаляется из рабочего
экспорта перед повторением, исходные файлы каталога не меняются.

## Расширение применимости существующих деталей — 10.10.2026

Владелец попросил находить остальные автомобили для уже импортированных деталей.
В установленном `Catalogue/Program/TMDVD.DAL.BDF.dll` подтверждены публичные методы:
`ArticleData.GetLinkedItemsV2(article)` возвращает обратные связи и признак
`CurrentArticle` / `ParentArticle`; `LinkageData.GetReverseArticleV2<T>(article,
vehicle, foundVia)` возвращает точные исходные последовательности, generic product,
атрибуты, общие условия, альтернативные блоки и текстовые ограничения.
`CurrentArticle` используется как основание прямой применимости. Связи через
родительский/сборочный артикул не превращаются в прямую применимость компонента.
Пропущенные области, отсутствующие в импортированном справочнике типы и
родительские связи учитываются в аудите, а не расширяются догадками.

`tools/catalog/CatalogFitments.cs` читает каждый артикул отдельно, затем его
подтверждённые точные типы. Группы определяются через собственное дерево целевого
автомобиля и исходную пару product/supplier; дерево Focus не копируется на другие
машины. Агрегирующие родительские узлы не создают лишних прямых назначений.
При ограничении прямого поиска по распространённому короткому номеру предусмотрен
поиск в полной коллекции конкретного исходного поставщика. Если точный артикул,
тип, последовательность или группа не подтверждены, экспорт завершается ошибкой.

Оптимизация: не читаются повторно OE/замены и сами детали; выгружаются только
добавочные категории и связи. Порции содержат до 50 целевых типов одного артикула
в каждой локали. Временный файл становится завершённым только после успешного
чтения всей порции. Фиксированный план, метки длины и SHA-256 позволяют возобновить
экспорт; 32-битный reader перезапускается после 100 обработанных типов либо при
превышении 900 МБ private memory. Импорт проверяет весь завершённый экспорт перед
записью и читает RU/EN порциями, не удерживая все связи каталога в памяти. Запись
транзакционная; ключ совпадает с исходным импортом:
`SHA256([variantId, partId, categoryId, productId, sequenceId])`.
В `attributes.importProvenance` хранится ссылка на batch, источник, выпуск,
страну, метод и вид связи. В batch сохраняются хеши, scope и аудит каждой локали.
Схема БД, URL локалей и публичные DTO не менялись.

Проверенные примеры из источника:

- FEBI BILSTEIN `06910`: P21/5W, 12 V, BAY15d; 10 047 прямых легковых типов.
- JOHNS `32 12 09`: 35 типов четырёх групп Focus II — hatchback, Saloon (DB_),
  Turnier и Convertible. Условие источника «Model year to: 01.2008» сохраняется;
  также сохраняются сторона, H7/H1 и требования к оборудованию из атрибутов.
  Это не утверждение о применимости ко всем Focus II независимо от выпуска.
- OSRAM `64193`: H4, 12 V, 60/55 W, P43t; reader вернул 7 055 прямых легковых
  типов и 52 коммерческих. Это read-only исследование; артикул не добавлялся в
  импортированный набор Focus. Правило «все машины до 1995» не используется.

**Доставленный образец:** FEBI — 9 типов, выбранных по реальным обратным связям
для проверки нескольких марок; JOHNS — все 35 возвращённых легковых типов.
Обе локали завершены. Образец содержит 25 категорий и 168 связей для 43 разных
типов; 10 связей уже существовали у Focus, добавлено 158. Локальная и облачная БД
содержат 26 729 связей, из них прежние 26 571 у `car:18953`. Прежние количества
деталей, OE, замен и справочника автомобилей сохранены. Повторные импорты в обе
БД не увеличивают количества. Batch: `catalog-2018q2-fitments-sample-f618eb99c940cc8c`.
Фара на Focus II 1.4 `car:18305` и лампа на Audi 80 `car:1394` проверены через
production API и браузер в RU/EN, включая ограничение 01.2008 и мобильный экран.
**Массовый проход по всем 11 305 артикулам ещё не выполнен; образец не является
полной поставкой обратных связей.**

Воспроизведение образца из корня workspace:

```powershell
./tools/catalog/invoke-export.ps1 -Mode fitment-probe
# После exit=0 у помощника:
node scripts/prepare-fitments.cjs --sample
./tools/catalog/invoke-export.ps1 -Mode fitments
# После FITMENTS_COMPLETE / exit=0:
node scripts/import-catalog.cjs --fitments --sample --validate
node scripts/import-catalog.cjs --fitments --sample
node scripts/import-catalog.cjs --fitments --sample --production
node scripts/verify-catalog.cjs --full
```

Для полного прохода существующих деталей после валидации образца: при завершённом
помощнике сохранить `.cache/catalog-fitment-export` отдельной папкой внутри
`.cache`, затем выполнить `node scripts/prepare-fitments.cjs` без `--sample`,
запустить тот же режим `fitments`, дождаться полного завершения и использовать
`node scripts/import-catalog.cjs --fitments --validate`, затем `--fitments`
локально и `--fitments --production` в облаке. Полный план содержит только уже
импортированные артикулы и типы; новые детали, фотографии и коммерческие машины
не импортируются. Долгий проход можно повторно запускать с тем же планом, не теряя
завершённые порции. Сменить план в той же папке нельзя. Архивный образец можно
проверять/импортировать через `--directory .cache/<папка-образца> --sample`.
`--sample` обязателен для образца и запрещён для полного плана: scope проверяется
по исходным файлам. ВМ и её каталог не изменяются; запуск использует существующую
desktop-сессию и общую папку. Host launcher вводит ASCII через Alt+numpad, чтобы
не зависеть от текущей RU/EN раскладки гостя.

Интерфейс: две карточки, строка поиска пока отключена с объяснением;
зависимые фильтры марки, модели, топлива, кузова, коробки и модификации;
дерево групп запчастей. Вторая карточка показывает выбранную модель,
звёздочку избранного и результаты конкретной группы. Выбор хранится в URL,
избранное — прежний контракт localStorage v1.
